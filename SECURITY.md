# Security policy

## Supported versions

Until this fork publishes its first stable release, only the current `main`
branch is eligible for security fixes. Historical upstream releases should be
reported to their respective maintainers.

## Reporting a vulnerability

Do not open a public issue for a vulnerability that could enable arbitrary code
execution, unsafe DLL loading, compromised release artifacts, credential or
token exposure, or practical supply-chain compromise.

Use GitHub private vulnerability reporting when it is enabled for this
repository. If private reporting is unavailable, contact the repository owner
privately before disclosing technical details.

Include:

- affected commit or release;
- affected game and SKSE versions;
- prerequisites and reproduction steps;
- impact and realistic attack model;
- logs, crash records, or proof of concept where safe;
- any known mitigation.

The project will acknowledge a complete report, assess severity, coordinate a
fix, and publish credit and disclosure details with the reporter's consent.
There is currently no guaranteed response-time service level.
